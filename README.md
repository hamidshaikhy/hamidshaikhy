## The front-end problems I enjoy

### UI architecture & state

Breaking an interface into reusable parts, defining clear state transitions and keeping application logic separate from presentation. I've worked with shared state across multiple views, browser persistence and execution logic that runs independently of React.

### Interaction & visual detail

Drag-and-drop interfaces, window movement and resizing, keyboard controls, theme switching and touch-friendly layouts. I enjoy making these details work together so that an interface feels consistent as users move through it.

### Documents & structured data

Live previews, measured A4 pagination, editable sections, import/export flows and data validation. These features bring together layout, state, persistence and the practical details of browser-based applications.

### RTL & multilingual interfaces

Persian typography, right-to-left layouts, Jalali dates and adapting interfaces for different languages. I pay attention to reading order, alignment and mixed Persian/English content.

### Reliability & testing

Loading, empty, error and interrupted states are part of the interface. My work includes unit and browser tests for workflow execution, cancellation and recovery, with an emphasis on behavior users can observe.

## How I approach a feature

1. **Understand the interaction.** Identify what the user wants to do, the information they need and the states the interface can enter.
2. **Build the structure.** Define the component boundaries, data shapes and state before adding visual polish.
3. **Make it usable.** Refine layout, typography, spacing and feedback, including responsive and RTL behavior.
4. **Check the edges.** Exercise invalid input, failures, interrupted actions and repeated interactions.
5. **Leave it understandable.** Document the feature, its limitations and how to run the project.
